## Основные фичи (суммарно максимум 60 баллов)

- [x] Все фичи должны быть адаптивными, так как фитнес-приложение логично использовать на телефоне или планшете. Отсутствие адаптивности приведет к снижению оценки.

### 1. Каталог упражнений (максимум 15 баллов)

Тренировки в вашем фитнес-приложении будут состоять из отдельных упражнений, а значит, надо реализовать функциональность для внесения упражнений и просмотра их списка.

- [x] У каждого упражнения должна быть инструкция в виде текста, картинок или видео, а также набор дополнительных атрибутов, таких как сложность (простое/среднее/сложное, можно ввести свою шкалу), список необходимого оборудования (гантели, скакалка, коврик и так далее) и дополнительные атрибуты-теги (например, «упражнение на ноги»). Пользователь должен иметь возможность добавлять упражнения в каталог, редактировать и удалять их.

- [x] Надо предусмотреть возможность фильтровать список упражнений по тегам, оборудованию и сложности.

- [x] Уже на старте приложение должно быть готово к использованию, поэтому мы просим предзаполнить каталог минимум 15 упражнениями. Контент значения не имеет, но, пожалуйста, не добавляйте 15 полностью одинаковых упражнений: это затруднит экспертам проверку и они не смогут в полной мере оценить ваше приложение.

### 2. Конструктор тренировок (максимум 15 баллов)

Из заведенных в каталоге упражнений пользователь может собрать план тренировки.

- [x] Приложение должно поддерживать как выбор упражнений вручную,
- [x] так и автоподбор по указанным тегам (например, по части тела, которую
      хочется проработать).

- [x] При создании тренировки для каждого упражнения можно регулировать число повторений, время выполнения или цель, в зависимости от типа упражнения. Например, для приседаний логично указывать число повторов, для бега — время, а для упражнений со штангой — вес.
- [x] Добавить подходы для повторений?

- [ ] Цель упражнения должна подбираться автоматически на основе параметров пользователя. Это можно реализовать по любой элементарной формуле, так как эксперты будут проверять работу приложения, а не знание методики тренировок. Пользователь также должен иметь возможность скорректировать цель вручную.

- [ ] Если пользователь указывает слишком большое число повторений или время выполнения, то приложение должно показать предупреждение о слишком высокой нагрузке.

- [x] Собранный план тренировки можно сохранить для переиспользования
- [x] или запустить разово.

- [x] Как и в случае с каталогом упражнений, приложение должно быть предзаполнено как минимум тремя разными тренировками.

### 3. Режим тренировки (максимум 10 баллов)

- [x] При переходе в режим тренировки пользователю надо показать упражнения для выполнения. Упражнения показываются в заданном при создании тренировки порядке. Если упражнение надо выполнять определенное время, приложение запускает таймер, а если пользователь должен сделать определенное число повторов, то приложение ждет сигнала, что пользователь закончил выполнение.

- [x] Между упражнениями запускается таймер на отдых на фиксированное число секунд, но пользователь также может увеличивать или уменьшать время по 10 секунд.

- [x] При необходимости пользователь может пропустить некоторые упражнения.

- [x] В конце тренировки приложение показывает статистику (например, сколько времени длилась тренировка, сколько сделано повторов).
- [x] добавить подходы? вес?

- [ ] За тренировки начисляются баллы, которые затем пользователь может потратить на кастомизацию персонажа (см. следующий раздел).

### 4. Персонаж (максимум 20 баллов)

- [x] У пользователя должен быть свой персонаж-аватар, который можно кастомизировать и который меняется по мере того, как пользователь выполняет тренировки. Чем больше пройдено тренировок, тем сильнее прогрессирует персонаж. Например, он может становиться более накачанным или, наоборот, стройным. Можно попросить пользователя выбрать цель тренировок.

- [x] Также в разделе «Персонаж» и при первом входе в приложение пользователь должен иметь возможность указать данные о себе, например свой рост и вес.
- [ ] Эта информация затем используется в конструкторе тренировок.

- [ ] Чтобы Васе было интересно заниматься, вы решили добавить элементы геймификации. За тренировки пользователю начисляются баллы и ачивки. Накопленные баллы можно тратить на кастомизацию персонажа: например, поменять прическу, одежду — на усмотрение разработчика приложения.

## Технические критерии (максимум 10 баллов)

За соблюдение следующих критериев вам будут начислены дополнительные баллы:

- Коммиты делались регулярно и содержали информативные сообщения (должно быть понятно, что вы сделали в этом коммите).
- Нет необработанных ошибок (ошибки в консоли, ошибки в UI при вводе невалидных данных и так далее).
- В проекте нет неиспользуемых файлов и кусков кода, а также закомментированных участков кода.
- Отсутствует дублирование кода.
- Отсутствуют длинные функции и методы (больше 20 строк), они логически разбиты на несколько небольших.
- Код разбит на логические части.
- Верстка корректна с точки зрения валидатора W3C (validator.w3.org).
- Приложение отвечает требованиям доступности WCAG 2.2 A (digitala11y.com/wcag-checklist). Для проверки можно использовать браузерные плагины или другие инструменты:
  - IBM Equal Access Accessibility Checker
  - axe DevTools
  - иные.

## Экспертная оценка жюри (максимум 20 баллов)

Дополнительно мы проверим работоспособность, качество и продуманность приложения в целом — как с точки зрения реализованной функциональности, так и с точки зрения технической реализации.

## Технические требования

1. Приложение должно быть задеплоено с использованием Gitlab Pages. Чтобы деплой сработал, добавьте в файл `package.json` команду `build`, которая сгенерирует статику в папку public.
2. Незадеплоенные приложения, а также приложения задеплоенные на сторонних платформах, проверяться не будут.
3. Редактировать файл `.gitlab-ci.yml` запрещается.
4. Приложение должно легко запускаться локально, см. раздел «Система оценки».
5. Можно использовать любой JS-фреймворк, также можно писать на TypeScript. Flutter, PHP и другие языки и фреймворки, которые не попадают в категорию JS/TS, использовать нельзя.
6. Можно использовать любые NPM-библиотеки, включая библиотеки компонентов. Но руководствуйтесь здравым смыслом и не тащите в проект лишнее.
7. Бэкенд и авторизацию делать не надо.
8. Запрещено сдавать чужие проекты или их форки.
